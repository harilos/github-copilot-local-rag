## Thin VS Code UAT boundary

The old Agent-002 directory now retains only `fixtures`, `sealed-dbs`, and
`workspace`. Its launcher, runtime manifests, VS Code user-data directory, and
extensions directory are absent. Recreating a profile would introduce a new
authentication/trust/bootstrap scope, so it was not inferred from the short
`LRR-AGENT-003` request.

Once a signed-in dedicated profile is provided, the thin UAT is:

1. Open this exact worktree in that profile.
2. Review/start `localRagAgent003`; accept the normal first-start MCP server
   trust prompt once.
3. Select `AGENT003-READONLY-RAG` and GPT-5 mini.
4. Send the natural question
   `関数 ledger_sync のメンテナンス窓はいつですか？` once.
5. Pass only if the native session records `local_rag_search`, selects
   `agent002-decoy-rag`, returns an answer with `[E1]`, and records no terminal,
   file, web, edit, or subagent call.

## Non-blocking observation

Closing stdio (the VS Code shutdown path) exits cleanly and is covered by the
protocol test. An interactive `Ctrl+C` produces a Python `KeyboardInterrupt`
traceback; this is a developer-console shutdown cosmetic issue and is not on
the MCP client path.
