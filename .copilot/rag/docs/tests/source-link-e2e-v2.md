# Source-Link Live URL E2E Specification v2

This specification verifies that Source-Link URLs generated by Local RAG
resolve to the intended external target. Normal lookup remains fully local and
never performs these HTTP checks.

All tracked examples use placeholders. Real organization, tenant, repository,
user, customer, and workstation names must not be committed.

## Levels

1. **Offline Contract** validates the one-Source/one-Provider contract,
   encoding, fail-open behavior, and result-bundle retention without external
   network access.
2. **Live Target E2E** performs explicit HTTP GET requests against a public
   GitHub fixture or a controlled loopback Redmine instance.
3. **Organization Smoke** is an optional, non-public check against one to
   three internal targets. Its report must use redacted URL reporting.

Only `run_source_link_e2e.py` performs Live Target E2E network access. Search,
the daemon, the manager's normal search operation, and result-detail lookup do
not validate URLs over HTTP.

The runner uses `rag-source-links-v2`: one Source contains one Provider,
enabled state, strategy, and settings object. The current visible catalog
documents define exactly one observed top-level stored root. That root
component is removed exactly once and the Source-relative path is passed to
the Provider. No user-entered Source-Link path prefix or longest-prefix
selection is involved.

## HTTP contract

```text
method:             GET
connect timeout:    3 seconds
overall deadline:   10 seconds
retry:              none
redirects:          maximum 3
successful fixture: HTTP 200
missing target:     HTTP 404
response body cap:  2 MiB
```

Redirects are followed only through explicit 301, 302, 303, 307, or 308
responses. A second request through another route is never attempted after a
real HTTP operation begins.

## Public GitHub fixture

Tracked synthetic files live under:

```text
.copilot/rag/docs/tests/source-link-fixtures/
├── plain.txt
├── nested/
│   └── document.md
└── 日本語 空白 #1 (final).txt
```

Every file contains:

```text
LOCAL_RAG_SOURCE_LINK_FIXTURE_V1
```

Create a dedicated tag or branch such as `<fixture-ref>` at the tested commit.
Pass the full commit ID separately for permalink validation.

Required cases:

| ID | Check |
| --- | --- |
| GH-E2E-001 | A normal ref URL returns 200 and identifies the fixture. |
| GH-E2E-002 | A full-commit permalink returns 200 and contains the commit. |
| GH-E2E-003 | Japanese text, spaces, `#`, and parentheses are encoded and return 200. |
| GH-E2E-004 | A ref containing `/` resolves correctly. |
| GH-E2E-005 | `source_permalink` is preferred when both links exist. |
| GH-E2E-006 | A missing file returns 404 without changing search status or ordering. |

The generated GitHub page is fetched first. If its HTML does not contain the
fixture marker, the runner performs a separate `?raw=1` content probe for the
same successful target. This is content verification, not a retry of a failed
request.

Example:

```bash
python .copilot/rag/docs/tests/run_source_link_e2e.py \
  --provider github \
  --repository-url "https://<git-host>/<owner>/<repository>" \
  --ref "<fixture-ref>" \
  --commit "<full-commit-id>" \
  --ca-bundle "<explicit-ca-bundle>" \
  --url-reporting public \
  --output "<temporary-output>/github-source-link-e2e.jsonl"
```

## Controlled Redmine fixture

Use a disposable loopback Redmine instance with a public synthetic project.
Create one issue whose subject contains:

```text
LOCAL_RAG_SOURCE_LINK_ISSUE_V1
```

Required cases:

| ID | Check |
| --- | --- |
| RM-E2E-001 | The generated issue page and `/issues/<id>.json` return the expected issue. |
| RM-E2E-002 | An unmatched stored path remains path-only. |
| RM-E2E-003 | A missing issue returns 404 without changing search status or ordering. |
| RM-E2E-004 | Base URLs with and without a trailing slash generate the same URL. |
| RM-E2E-005 | Invalid template, group, credential, token, and regex settings are rejected. |

Example:

```bash
python .copilot/rag/docs/tests/run_source_link_e2e.py \
  --provider redmine \
  --redmine-base-url "http://127.0.0.1:<port>" \
  --issue-id "<fixture-issue-id>" \
  --url-reporting redacted \
  --output "<temporary-output>/redmine-source-link-e2e.jsonl"
```

The Wiki target is optional because its API compatibility may vary between
Redmine versions.

## Reporting and security

JSONL records include the case ID, provider, expected and actual status,
latency, marker verification, search-invariance result, and pass/fail result.

`--url-reporting redacted` is the default. It stores only a SHA-256 URL digest
and omits the host and path. Public GitHub fixtures may explicitly use
`--url-reporting public`.

The runner:

- accepts no authorization token, cookie, password, or private key;
- never logs request headers;
- never stores credentials in a fixture or report;
- honors `SSL_CERT_FILE` or `REQUESTS_CA_BUNDLE` for an explicitly supplied
  CA bundle, supports `--ca-bundle` with higher precedence, then uses the
  installed Python CA bundle or system defaults;
- never disables TLS certificate verification;
- performs no Git discovery and runs no Git command;
- creates no database or index content;
- does not copy reports into release archives.

## Release gates

```text
GitHub required cases:               6/6 PASS
Redmine required cases:              5/5 PASS
Offline Source-Link contracts:       PASS
credential leakage:                  0
normal-search external HTTP calls:   0
URL failures causing search failure: 0
ranking/status/authority changes:    0

```

Organization smoke results are informative and must not be committed.
